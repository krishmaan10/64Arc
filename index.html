Stock, price, dues, credit limits — each number is owned in one place, and every screen goes back to that place to read it. Where a branch’s figure has not reached head office yet, the screen says so instead of guessing.

Customer, stock, price, credit limit — each has one place that owns it, and every screen and every integration resolves against that owner. Where a branch’s figure has not reached head office, the screen shows which source it used and how old it is.

In the estate we built for, every branch feeds a central copy. Two in three branches are on the live stock feed; the rest fall back to an older one, and two are dormant. The read layer picks the source branch by branch, stamps the row with the date it is as of, and keeps the dormant branches out of cross-branch availability.

Your ERP stays the system of record

The system of record stays

It is written for your business, not bought and bent to fit. We read from the system your books already run on, write back into it, and add what it was never built to hold — field visits, orders, attendance, credit decisions.

Built to your process, integrated with what you already run. Nothing has to be migrated. We read from the ERP and write back through it; what it has nowhere to put — field activity, attendance, credit decisions — goes to a store of our own, beside it, not inside it.

In the one we built, the ERP is about 1.1 million lines of hand-written VB.NET and is still the system of record. A separate write store on managed Postgres holds what it cannot: field activity, orders, attendance, credit decisions. The captured order lives there; the priced sales order lives in the branch ERP, as it always has.

The interface each role needs

Different apps, one write path

A rep on a bike, a dealer at midnight, a supplier, a clerk at the counter and you on a Sunday — phone, website or desk, in the language each one reads. The app is in thirteen. An order taken where there is no signal waits on the phone and goes in when the signal returns. It cannot go in twice.

Reps in the field, dealers ordering at night, suppliers, admin staff at head office and directors reading the month each get their own application on the same orders, stock and dues — web and phones, in thirteen languages. Orders taken without signal queue on the device and post when it returns; the same order cannot be booked twice.

Reps, dealers, suppliers and head office each get their own app — Android, installable web, thirteen locales. The device holds an outbox for orders taken offline; it holds no rules. Each order carries a client-generated key, so a timed-out post that the phone retries is deduped rather than booked twice — and the file the branch ERP receives is keyed the same way, so it cannot be applied twice there either.

What happens when you press save

The rules run on the server

The rules live on the server

The screen is the easy part. Before an order is saved, the dues and the credit limit are checked against head office’s own record of that dealer — nobody has to ring anyone. Over the limit, the order still goes through, marked, with the reason kept on it. A payment and the photograph of its receipt are recorded together, or neither is.

Screens are the small part. Credit is re-checked on the server against head office’s own dealer record before an order is written — a soft block, not a refusal, and where someone ticks through, the reasons stay on the order and show on its card. A payment and its proof photograph commit together, or neither is recorded. A rule changes in one place and every application follows.

Credit is re-derived server-side and the write returns 409 with the reasons unless the client acknowledges, so a stale or modified phone cannot talk its way past it — a soft block, with the acknowledged reasons persisted on the order row. A payment and its proof photograph arrive in one multipart request and commit on one connection: there is no window in which a payment exists proof-less, and a client too old to send the pair is refused. Orders travel carrying no rates; the branch ERP prices them from its own masters at save.
